# Validation sequence - shared external-provider credentials

The external role provider now uses the same credential factory as application configuration. This run validates integration and anonymous authorization smoke behavior, not a live cloud client-secret exchange.

## ✅ Automated verification (✅ done)

The 42 focused tests cover shared credential configuration, Development-only JWT restrictions, legacy configuration compatibility, malformed credentials, disabled-provider behavior, and loading the actual published plugin with both credential paths. The locked Release ZIP includes the shared factory and its required dependencies. The persisted configuration keeps the external provider disabled.

## ⚠️ Notes

Normal credentials are delegated to `DefaultCredentialProvider`, not a new bespoke credential chain and not `Azure.Identity.DefaultAzureCredential`. It reads the external provider's own settings. The Development JWT remains a separate explicit override.

No Azure deployment, secret creation, permission grant, or real cloud token request was performed. Browser validation covers startup and anonymous denial only; signed-in role resolution and hosted credentials still need validation with authorized credentials. The owned validation host was stopped after capture.
