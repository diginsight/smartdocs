# Validation sequence: role-provider enable switch

This run verifies that one environment variable selects the external provider without weakening repository policies. Deployment-specific identifiers and all screenshots remain in the internal companion.

## 🧪 Environment

Each state used a fresh reader sign-in after the server was rebuilt and restarted.

| Item | Value |
|---|---|
| URL | `https://localhost:7280/` |
| Switch | `Site__Authorization__RoleProvider__IsEnabled=false` or `true` |
| Build and run | Rebuilt Debug server/client, foreground visible PowerShell console |
| Browser | Independent headed Edge, viewport `1015 x 1118` |
| Date | November 19, 2026 |

## ✅ Sequence and results

Live DOM reads and browser responses established these results.

## 📷 Evidence

The internal companion contains a screenshot and provenance sidecar for every browser case, plus exact route and heading observations.

Console-only checks also passed: **189 authorization/provider assertions**, **30 focused private configuration/loader tests**, and offline deployment regressions. The actual Release ZIP includes the private provider and its dependencies even while its official activation flag is false. Its settings exclude Development overlays. A separate locked x86 provider publish also passed.

## ⚠️ Notes

Disabling the external provider selects Entra token roles; it doesn't disable authorization. Existing authentication cookies retain their old role snapshot until renewed or expired.

No Azure deployment or identity change occurred. Hosted identity federation, hosted DiMa access, and deployed storage access weren't validated. Existing dependency advisories remain unchanged. The retained package and environment-specific screenshots stay in the private checkout.
