## 🔎 Root cause and correction

The vault secret was already enabled before the failing host started. Shared local settings cleared `AzureKeyVault:Uri`, so the configuration loader never registered the vault provider. The environment-local overlay now restores that environment's URI without placing a secret value in configuration or changing other profiles.

The previous run proved role resolution with an injected credential. This run additionally proves credential loading through the normal application configuration.

## ⚠️ Notes

Fully stop and restart the original host after the correction; sign-out alone doesn't register its missing vault provider. The test used the normal launch profile on alternate ports, not a literal Ctrl+F5 invocation inside Visual Studio.

No C# code or cloud setting changed. The previous automated suite wasn't rerun; verification used the rebuilt application and browser sequence above. The Development-only overlay isn't packaged, so the existing deployment ZIP is unaffected. The separate test host was stopped; the original process was preserved. Hosted behavior wasn't tested.
